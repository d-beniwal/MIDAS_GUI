# Pip requirements for midas-gui, generated from environment.yml.
#
# Fully pinned to the verified-working set. The key compatibility constraint:
# numba 0.59.x requires NumPy < 2.1 and torch 2.4.0 targets NumPy 1.x, so numpy
# is pinned to 1.26.4 and the MIDAS backends to their NumPy-1-era releases. Do
# NOT bump numpy to 2.x here without also moving torch to >=2.3 and the
# backends to their newer (numba 0.66 / NumPy-2) releases — mixing the two
# families breaks `torch.from_numpy` ("Numpy is not available").
#
# NOTE on PyQt5: environment.yml installs Qt bindings from conda-forge (not
# pip) because the pip PyQt5 wheel bundles its own Qt5 libs but dlopens
# xcb-side system libraries (e.g. libxcb-cursor.so.0, required since
# PyQt5-Qt5 5.15.9+) at runtime instead of vendoring them. On at least one
# beamline Linux workstation this caused a silent startup hang (no error,
# unresponsive to Ctrl+C — a native deadlock inside Qt's xcb platform plugin).
# If you hit that with the pip wheel below, use a conda/mamba env with
# environment.yml instead, or `apt install` the missing libxcb/xcb-util-cursor/
# libxkbcommon-x11 system libraries.
